# The Training Loop — Make the Model Tell the Truth

A small transformer and a real training loop made observable from first principles. The complete assignment is implemented directly in `training_loop_truth.ipynb`; there is no wrapper or external experiment script required to understand or run the work.

## What the notebook contains

| Requirement | Evidence in the notebook |
|---|---|
| Print every tensor shape | Explicit transformer forward pass records tokens, embeddings, Q/K/V, attention scores and weights, context, MLP tensors, logits, flattened loss tensors, scalar loss, parameters and gradients. `B, T, C, H, D, F, V` are defined and every printed tensor has a one-line axis explanation. |
| Verify one gradient by hand | A scalar output-head weight is nudged by `±epsilon`; central finite difference is compared with `backward()` using float64 and asserted to relative error below `1e-6`. |
| Break gradient accumulation | Unequal **96-token** and **384-token** micro-batches intentionally use average-of-averages, while the correct path uses token-weighted normalization. Both loss curves are plotted together. |
| Prove the normalization | A same-distribution reference experiment shows correct sequential accumulation reproduces the exact combined-token gradient, while the broken rule does not. |
| Log grad norm every step | Global L2 gradient norm and fixed probe loss are printed at every optimizer step; the notebook identifies a step where grad norm moves before loss. |
| Compute MFU | Step time and explicit model FLOP accounting are combined with an exposed peak denominator. The notebook reports MFU and the percentage-point gap to 40%, then explains the causes of the gap. |
| Write out 0.1 by hand | The binary expansion, exponent bias, retained mantissa bits, rounding decision, final bits and hex are shown for fp32, bf16 and fp8 E4M3. BF16 is selected for training and justified. |

## Floating-point result

```text
0.1₁₀ = 0.00011001100110011…₂
      = 1.1001100110011…₂ × 2⁻⁴

fp32      0 | 01111011 | 10011001100110011001101   0x3DCCCCCD
bf16      0 | 01111011 | 1001101                   0x3DCD
fp8 E4M3  0 | 0011     | 101                       0x1D
```

BF16 is the preferred training format among these three on hardware with native BF16 support because it preserves fp32-like exponent range while reducing memory and bandwidth pressure.

## Reproduce from scratch

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# macOS/Linux: source .venv/bin/activate

pip install -r requirements.txt
jupyter nbconvert \
  --to notebook \
  --execute training_loop_truth.ipynb \
  --output training_loop_truth.rerun.ipynb \
  --ExecutePreprocessor.timeout=300
python verify_assignment.py
```

## Reproducibility

- deterministic seeds for correctness experiments
- no external dataset or network download
- explicit training step rather than a trainer abstraction
- identical initialization for wrong/correct accumulation comparison
- same-distribution reference-gradient proof
- fixed token-weighted evaluation for accumulation curves
- global grad norm logged every step
- machine-readable metrics regenerated by the notebook
- assertions fail loudly when numerical invariants are violated
- GitHub Actions executes the notebook from a clean checkout before verification

## Takeaway

A training loop can produce a plausible loss curve while optimizing the wrong objective. The defense is falsifiable observability:

**shape the tensors → nudge a weight → break and prove accumulation → watch the norm → account for the FLOPs → inspect the bits.**
